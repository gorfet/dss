# Dynamic Faculty Evaluation System (360°)

## Goals
- Provide a secure, configurable 360° evaluation system for faculty performance.
- Enforce strict role-based access and anonymize student feedback.
- Deliver actionable analytics across semesters and departments.

## Role-Based Access Model
| Role | Key Capabilities | Data Visibility |
| --- | --- | --- |
| Admin | Create evaluation periods, forms, weights, and manage users. | Full system scope, audit logs. |
| Faculty | View anonymized feedback, submit self-evaluations, action plans. | Own evaluations only. |
| Student | Submit anonymous evaluations for enrolled courses. | Own submissions only (no identity exposure). |
| Peer Evaluator | Provide peer feedback for assigned faculty. | Assigned evaluations only. |
| Department Head | View department faculty summaries, approve action plans. | Department scope only. |
| Alumni/External | Provide feedback for assigned faculty. | Assigned evaluations only. |

## Evaluation Periods
- Semester-based evaluation windows with open/close timestamps.
- Submission locking after deadline; late submissions rejected.
- Reminders and notifications scheduled for incomplete submissions.

## Form Builder
- Admins create evaluator-group-specific forms.
- Sections mapped to categories (Teaching Effectiveness, Subject Mastery, Classroom Management, Professional Ethics, Research & Innovation, Community Engagement).
- Supported question types: Likert 1–5, multiple choice, short/long text.
- Versioning by creating a new form per period; previous forms remain read-only.

## Security & Privacy
- JWT/OAuth authentication.
- RBAC enforced by route middleware and scoped queries.
- Student submissions anonymized via non-reversible tokens; evaluator identities never exposed to faculty.
- Audit logs for changes to weights, forms, and evaluation outcomes.
- FERPA-like privacy: least privilege, data retention policies per institution.

## 360° Weighting Logic
- Weights are stored per evaluation period in the database and validated on read.
- All category scores normalized to a 0–100 range, then aggregated.
- Group weights are immutable once an evaluation window opens.

## Analytics & Reporting
- Radar charts for competency categories.
- Trend lines across semesters.
- Department dashboards (aggregate and distribution).
- Exportable PDF and Excel reports generated by server-side jobs.

## Data Flow
1. Admin creates evaluation period, evaluator group weights, and forms.
2. Assignments are generated (course enrollment, peers, department head, alumni).
3. Evaluators submit responses; submissions lock after close.
4. Scoring engine normalizes category scores and applies weights.
5. Dashboards and exports use the snapshot tables for performance.

## AI-Powered Intelligence (Optional)
- Sentiment analysis on free-text responses.
- Bias detection on unusually high/low variance evaluators.
- Summary generation and improvement recommendations.

## Key API Surface (Summary)
- `POST /api/evaluation-periods` create evaluation window.
- `POST /api/forms` create evaluator-specific forms.
- `POST /api/assignments` generate assignments.
- `POST /api/submissions/:id/submit` submit and lock.
- `GET /api/analytics/faculty/:id` faculty analytics summary.
